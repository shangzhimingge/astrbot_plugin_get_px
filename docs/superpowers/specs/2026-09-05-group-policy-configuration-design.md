# 群策略配置界面设计

## 背景与目标

当前群内容安全策略已保存在 SQLite，但 WebUI 只能输入一个群 ID 后读写单条策略，刷新时候选群列表又来自签到数据，因此手动添加的群刷新后不再可见。

本次增加独立的“群策略配置”界面，让 AstrBot 插件配置页和插件 WebUI 都能持久化地查看、添加、编辑和删除群策略。两个界面必须使用同一数据源，刷新或重启后保持一致。

## 产品语义

每条群策略包含：

- `group_id`：非空群 ID，去除首尾空白后最长 128 个字符。
- `general_only_enabled`：是否强制只使用普通分级，默认为开启。
- `builtin_terms_enabled`：是否启用内置安全词，默认为开启。

未在列表中的群使用默认严格策略，即两项都开启。私聊始终使用该默认严格策略。全局自定义安全词和作品 ID 黑名单不受群策略开关影响。

用户删除一条群策略时，系统删除该群的显式记录，该群立即恢复默认严格策略。

## 数据架构

### 唯一数据源

新增 `_conf_schema.json` 配置项 `group_content_safety_policies`，类型为 AstrBot `template_list`。每个模板条目对应一个群，并由 `group_id` 作为折叠列表的显示字段。插件配置中的该列表是唯一权威数据源。

运行时将配置列表规范化为以群 ID 为键的策略映射。发图流程和 Web API 只通过一个群策略服务读写该映射，避免各处自行解析配置。

### SQLite 升级迁移

插件首次运行新版本时：

1. 若新配置列表已有内容，直接以配置列表为准。
2. 若新配置列表为空且尚未完成迁移，读取 SQLite `group_content_safety` 中的所有现有记录，写入配置并保存。
3. 记录隐藏的一次性迁移标记。标记存在后，空列表表示用户确实删除了全部策略，不再从 SQLite 回填。
4. 迁移完成后，旧表仅作升级来源，不再参与日常读写。

如果配置保存失败，本次迁移不设置完成标记，保留 SQLite 原始记录，并在下次启动时重试。

## 界面设计

### AstrBot 插件配置页

新增独立的“群策略配置” `template_list`：

- 点击添加后打开一个群策略编辑条目。
- 条目内包含群 ID 以及两个独立开关。
- 折叠后使用群 ID 区分各条记录。
- 配置页自带条目删除能力，保存整份插件配置后生效。
- 插件载入时对空 ID、超长 ID、重复 ID 和非布尔开关执行校验；无效条目不进入运行时映射，日志记录可定位的索引和原因。

### 插件 WebUI

管理中心导航新增独立的“群策略配置”页，原“内容安全”页保留安全词和作品黑名单管理，不再包含手动输入群 ID 的单条表单。

新页布局：

- 左侧为已持久化群策略列表，支持按群 ID 搜索，并显示两个开关的摘要状态。
- 列表顶部提供“添加群”按钮。新增时用户输入群 ID，初始开关均为开启。
- 右侧为当前群策略编辑器，包含两个开关、最后保存时间、保存修改和删除群。
- 窄屏下改为上下布局，保持键盘操作、聚焦回退和屏幕阅读提示。
- 列表数据从群策略 API 加载，不再依赖签到群列表。

## API 与数据流

群策略 API 保持管理端现有访问边界，并增加完整 CRUD：

- `GET content-safety/group-policies`：返回全部显式群策略，按群 ID 稳定排序。
- `GET content-safety?group_id=...`：保留单群查询兼容性。
- `POST content-safety/group-policy`：新增或更新一条策略。
- `POST content-safety/group-policy/remove`：删除一条策略。

写操作流程为：校验请求 → 在内存副本上应用变更 → 写回 `AstrBotConfig` 并调用 `save_config()` → 成功后替换运行时映射。保存失败时恢复原配置和原映射，API 返回统一错误，详细异常仅记录到插件日志。

插件配置页由 AstrBot 保存配置后，插件重载并重建同一运行时映射。WebUI 下次刷新时即读取相同数据。

## 错误处理与一致性

- 群 ID 在所有入口使用同一规范化函数。
- 重复群 ID 不创建第二条记录；WebUI 新增时提示“该群已存在”，配置载入时保留首条有效记录并记录警告。
- WebUI 保存期间锁定当前编辑器，防止重复提交。
- 删除前显示确认窗口，明确说明删除后恢复默认严格策略。
- 任何写入失败都不提前更改界面中的服务器已保存状态；重新加载后仍显示上次有效值。

## 测试与验收

### 单元与集成测试

- 配置列表规范化：有效条目、空 ID、超长 ID、重复 ID、非布尔开关。
- SQLite 首次迁移：有旧数据、无旧数据、新配置已存在、保存失败重试、迁移后空列表不回填。
- API：列表、新增、修改、删除、重复新增、参数校验和配置保存回滚。
- 运行时：未配置群和私聊严格；已配置群的两个开关独立生效。
- 前端合约：独立导航、持久化列表、添加、编辑、删除、空状态、失败回复和窄屏布局。

### 验收条件

1. 在任一界面添加群策略并保存后，刷新 WebUI 和重新打开插件配置页均能看到该群。
2. 在 WebUI 修改策略后，重新打开插件配置页可见相同值；在配置页修改并保存后，刷新 WebUI 可见相同值。
3. 从任一界面删除群后，该群不再出现于持久化列表，运行时两项开关均恢复开启。
4. 升级前 SQLite 中已保存的群策略会自动出现在新列表中，不丢失原有开关值。
5. 运行完整测试集后，既有发图、安全词、黑名单和签到功能保持通过。

## 兼容性与非目标

- 项目已要求 AstrBot `>=4.16`，因此可直接使用 `template_list`。
- 保留现有单群查询和更新 API 的请求语义，降低升级影响。
- 本次不改变私聊策略、全局自定义安全词、作品黑名单或签到群管理。
- 本次不增加群名称同步；持久化标识仍使用稳定的群 ID。
