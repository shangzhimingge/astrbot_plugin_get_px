# 会话内容安全策略与界面优化设计

## 目标

将当前功能完整但视觉层级薄弱的“群策略配置”升级为与插件管理中心全局樱花粉白设计一致的“会话策略配置”。在保留群策略持久化、迁移和回滚语义的同时，新增按私聊用户 ID 分别配置“强制普通分级”与“内置安全词”的能力。

## 范围与非目标

### 范围

- 优化插件 WebUI 的会话策略页，统一使用现有色彩、圆角、边框、阴影、间距、标题和状态样式。
- 将群聊与私聊用户策略收纳在同一页的分段切换中。
- AstrBot 插件配置页分别提供群聊和私聊用户的原生窗口化 `template_list`。
- 为私聊用户增加持久化策略、运行时解析、管理 API 和回归测试。

### 非目标

- 不改变全局自定义安全词与 Pixiv 作品黑名单语义。
- 不合并群 ID 和用户 ID 的数据命名空间。
- 不增加批量导入、批量删除或策略继承功能。
- 不改变已有群策略配置键或 SQLite 一次性迁移结果。

## 产品语义

群聊策略以群 ID 为键，私聊策略以发送者用户 ID 为键。每条策略包含两个互相独立的布尔开关：

- `general_only_enabled`：是否强制只允许普通分级。
- `builtin_terms_enabled`：是否启用内置安全词。

未显式配置的群和私聊用户均默认两项开启。删除某个群或用户的策略记录后，该对象立即恢复严格默认值。两项都开启的显式记录仍保留在列表中，只有删除操作移除记录。

## 数据架构

### 配置键

- 群聊：继续使用 `group_content_safety_policies`。
- 私聊：新增 `private_content_safety_policies`。

两者都是 `template_list`，条目各自使用 `group_id` 或 `user_id`。私聊列表初始为空，不需要数据迁移。既有群配置键、隐藏迁移标记和 SQLite 迁移逻辑保持兼容。

### 策略服务

将已有群策略服务抽取为可复用的会话策略存储单元，内部分别维护群和私聊用户的不可变快照。公开调用保持明确：

- 群聊：列表、查询、新增或更新、删除。
- 私聊：列表、查询、新增或更新、删除。

两个命名空间分别校验 ID、分别保存配置并分别回滚。对一类策略的写入失败不会影响另一类的运行时快照。

### 运行时解析

每次生成内容安全策略时：

1. 从事件读取群 ID。
2. 群 ID 非空时查询群策略。
3. 群 ID 为空时读取发送者用户 ID，查询私聊策略。
4. 事件为空、对应 ID 为空、ID 校验失败或策略服务异常时，使用严格默认值。

## API 设计

现有群策略 API 路由和响应语义保持不变。新增对称的私聊用户 API：

- `GET content-safety/private-policies`
- `POST content-safety/private-policy`
- `POST content-safety/private-policy/remove`

既有 `GET content-safety` 增加可选 `user_id`查询，但不传 ID 时仍只返回全局安全词与默认策略摘要。同时传入 `group_id` 与 `user_id` 时返回 400，防止作用域混淆。

API 保存流程继续使用“候选快照 → `save_config()` → 成功后替换运行时快照”。参数校验返回 400，服务尚未就绪返回 503，持久化异常使用现有统一错误响应并恢复上次有效状态。

## WebUI 设计

### 页面结构

管理中心导航将“群策略配置”改为“会话策略”。页面继续使用 `CONTENT GUARD` 标识，增加“群聊策略 / 私聊策略”分段按钮。切换仅改变当前目录、对象名称和 API 作用域，编辑器和反馈模式共用。

### 视觉层级

- 使用已有 `--surface`、`--border`、`--primary-soft`、`--secondary-soft`、`--safe-soft`、`--danger-soft` 与圆角阴影令牌，不引入第二套颜色系统。
- 页面标题、说明、数量与分段切换形成首屏层级。
- 左侧目录卡片包含搜索、添加和数量；条目显示 ID 及两个文字状态徽章，不仅依赖颜色。
- 右侧编辑卡片显示对象类型、ID、保存时间、两个卡片式开关和主次分明的操作区。
- 编辑主操作使用樱花粉主色，对象类型和次要信息使用浅蓝，成功状态使用绿色，删除使用已有危险色。
- 空状态在目录和编辑区均显示明确文案和添加入口，不显示空白面板。
- 加载、保存和删除期间统一禁用相关控件，同时显示文字状态和 `aria-busy`。

### 响应式与可访问性

- 桌面端左右双栏，目录稍窄、编辑器较宽。
- `<=900px` 改为上下布局；`<=620px` 收紧间距并让主要操作按钮占满可用宽度。
- 分段切换使用真实按钮、`aria-pressed` 与可见焦点。
- 列表使用真实按钮，选中状态同时用边框、背景和文字表达。
- 对话框保持焦点回退；删除最后一条记录后聚焦回到“添加”按钮。

## 状态与交互

群聊与私聊各自维护服务器列表、当前选中 ID、已保存快照与编辑草稿。切换类型时：

1. 若当前草稿与快照不同，显示放弃修改确认。
2. 确认后恢复原快照，切换到目标类型已保存的上次选中项。
3. 取消时保留当前类型和草稿。

新增、保存、删除和失败回滚与现有已验证语义一致。群 ID 与用户 ID 在各自列表内唯一，相同字符串可同时存在于群与用户命名空间。

## 错误处理

- ID 必须为字符串，去除首尾空白后非空，最长 128 个字符，且不包含控制字符。
- 开关只接受真正的布尔值。
- 重复新增不创建第二条记录，而是选中已有对象并提示。
- 保存失败时恢复配置对象、运行时快照和编辑器已保存值。
- 私聊策略服务不可用时，私聊内容运行时回退为严格默认。

## 测试与验收

### 测试

- 配置服务：两个命名空间隔离、显式严格条目保留、独立回滚、私聊列表默认为空。
- 运行时：群聊命中群策略，私聊命中发送者策略，未配置或 ID 读取失败时严格。
- API：私聊列表、新增、更新、删除、幂等删除、400、503 和保存回滚。
- WebUI：群/私聊切换、未保存草稿确认、两类状态隔离、精确 busy 禁用、删除相邻选择和时间显示。
- 视觉合约：设计令牌复用、状态徽章、空状态、两档响应式、焦点和 `aria-pressed`。
- 完整回归：已有群策略迁移、内容安全词、黑名单、发图和签到测试保持通过。

### 验收条件

1. WebUI 与插件配置页均可持久化地添加、修改和删除私聊用户策略。
2. 群聊与私聊使用各自 ID 命名空间，相互不覆盖。
3. 未配置对象和删除后对象均返回两项开启的严格默认值。
4. 群消息仅查询群策略；私聊消息仅查询发送者用户策略。
5. 切换类型或对象时，未保存草稿不会静默丢失。
6. 任一写入失败都不改变持久配置、运行时快照或另一作用域。
7. 会话策略页在颜色、圆角、间距、字体、状态和响应式上与管理中心现有界面一致。
8. 定向测试、完整测试、JavaScript 语法检查、JSON 校验和 diff 检查全部通过。
